About CreditGuard AI

Explore the engineering methodology and machine learning architecture.

1. Machine Learning Methodology

Retail banks face high default risks if credit card applications are not scrutinized. To evaluate creditworthiness objectively, this platform automates card risk classifications using a custom statistical model trained on Kaggle's Credit Card Approval Dataset.

To derived class labels, applicant timeseries credit histories are aggregated: applicants with debt payments $\ge 60$ days delinquent (status 2, 3, 4, 5) are labeled as default cases (Class 1). Class imbalance (~7.5% defaults vs 92.5% approvals) is handled using Random Oversampling during training, which enforces model generalization for high-risk profiles.

2. Architecture Pipeline

1. Ingestion
Loads Application and Credit CSV datasets from storage.
2. Processing
Imputes outliers, missing types, and maps scale features.
3. Benchmarking
Fits Logistic Regression, DT, RF, and XGBoost models.
4. Serving
Hosts the best model via Flask and REST APIs.

3. Security & Validation Standards

The system enforces robust security validation and application engineering practices:

  • WTForms Validation: Restricts invalid input variables and caps numeric ranges (e.g. Age 18-100) before predicting.
  • Explainable AI: Uses local Ridge regression perturbations to calculate local feature impact weights.
  • API Rate Limiting: Implements a custom sliding-window decorator protecting database transactions and scoring endpoints against DDoS loads.
